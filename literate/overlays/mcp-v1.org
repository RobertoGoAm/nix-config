#+TITLE: overlays mcp-v1

#+PROPERTY: header-args:nix :tangle (my/lit-target) :comments org :mkdirp yes

* semgrep still writes mcp 1.x against an mcp 2.x in the set

nixpkgs moved =mcp= from 1.x to 2.x, and 2.x renames the thing semgrep reaches
for:

  ModuleNotFoundError: No module named 'mcp.server.fastmcp'. This is mcp 2.x,
  where FastMCP was renamed to MCPServer

It is not a test failure dressed up as one. =semgrep/cli.py= imports
=semgrep.commands.mcp=, which imports =FastMCP= at module scope, so the import
fails before any command runs -- the build happens to notice it in conftest,
and a shipped =semgrep= would be a binary that cannot start. Its pyproject
still pins =mcp==1.29.0=.

nixpkgs kept =mcp_1= -- 1.29.0 -- in the python set for exactly this, so
semgrep needs no patching, only the argument it was written for.

** Scoped to semgrep, not to the set

Replacing =mcp= across =pythonPackagesExtensions= would hand 1.29.0 to
everything, including whatever has already been ported to 2.x, so semgrep takes
=mcp_1= through its own =override=.

This stops mattering the day semgrep ports, and the cost of leaving it behind
is an override that resolves to the same thing twice.

#+begin_src nix
final: prev: {
  pythonPackagesExtensions = prev.pythonPackagesExtensions ++ [
    (pyFinal: pyPrev: {
      semgrep = pyPrev.semgrep.override { mcp = pyFinal.mcp_1; };
    })
  ];
}
#+end_src
