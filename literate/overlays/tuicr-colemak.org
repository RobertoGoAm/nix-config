* tuicr's keys by physical position on a Colemak board

tuicr's keys are vim's and cannot be remapped: its config takes a =leader=
and nothing else, and every binding is a literal character in
=src/input/keybindings.rs=. Like the other keyboard-driven tools here, it should
answer on the physical keys its QWERTY defaults sit on, so Colemak =n=, =e=,
=i= move down, up and right, Colemak =k= is search-next, and so on for every
letter.

So the patch translates at the one place every key arrives: where the event
loop in =src/main.rs= reads an event, before the release tracking, the pending
leader, =z= and =d= prefixes and the per-mode key maps see it. A Colemak letter
becomes the QWERTY letter on the same physical key, Ctrl chords included (so
Ctrl+d and Ctrl+u stay put). Nothing is translated while text is being typed:
in a comment, a =:= command, a =/= search, or a file-tree, pull-request or theme
filter prompt. Punctuation is left alone, so =;= stays the leader and =:= still
opens a command line, and the key at QWERTY's =;= position, Colemak =o=, gives
=;= and, shifted, =:= as well.

The translation itself lives beside this file in =tuicr-colemak.rs= and is
appended to =main.rs=; the one substitution that calls it fails the build if the
line it replaces changes, which is when this needs looking at again.

#+begin_src nix
final: prev: {
  tuicr = prev.tuicr.overrideAttrs (old: {
    postPatch = (old.postPatch or "") + ''
      substituteInPlace src/main.rs --replace-fail \
        'let event = event::read()?;' \
        'let event = colemak_positions(&app, event::read()?);'
      cat ${./tuicr-colemak.rs} >> src/main.rs
    '';
  });
}
#+end_src
