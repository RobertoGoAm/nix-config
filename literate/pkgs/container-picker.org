* Asking which jar a link from outside the browser belongs in

A link clicked in Telegram, in a terminal or in a mail client lands in whatever
space happened to be in front, because that is what Zen's ~most-recent-space~
default means. The routes in =features/internet/zen.nix= answer this for the
hosts they know, and they cannot answer it for the rest: a Google Docs URL
carries no account index, and the one hostname that would say whose it is
cannot be in a public repo.

Nothing off the shelf asks. The container add-ons that handle external links --
=open-url-in-container=, =containerise=, Default Container Handler -- all answer
the question ahead of time, with a fixed container or a URL rule, and the
pattern they share is a custom =ext+container:= protocol the sender has to use.
Telegram will not. Multi-Account Containers does prompt, but only for a site
already assigned to a container and opened in the wrong one, which is the case
that was never in doubt.

So this asks. The tab is held before it loads, a page lists the containers, and
the answer makes the tab.

** The interception has to block, and it has to be in webRequest

Watching =tabs.onUpdated= is a race the browser wins. By the time a tab event
arrives the request is already on the wire, carrying whichever container the tab
was born in, and a cookie set in the wrong jar cannot be taken back. A blocking
=onBeforeRequest= holds the request, so nothing leaves until the container is
chosen.

That listener is synchronous, and that shapes the rest: an async handler would
hold every top-level request in the browser for the length of a storage read.
The tab ages and the remembered hosts are therefore kept in memory and refreshed
from events, never read from storage on the hot path.

** Telling an external link from everything else

An external link has no document behind it, so =originUrl= and =documentUrl= are
both absent -- which rules out every link clicked on a page. Address-bar typing
and bookmarks arrive the same way, and what separates them is the tab's age: an
external link creates a tab and navigates it in one breath, while opening a tab
and then typing into it does not.

** Choosing a container means making a new tab

=cookieStoreId= is settable only at =tabs.create= time; no API moves a live tab
between containers. Every path here therefore ends in a new tab at the old
one's index, and the old one closing. It is also why the picker page cannot
act on itself and messages the background page instead.

** Zen's routing still runs

A route that matches sends the tab to its space regardless, and the two can
disagree. The remembered hosts are the way out: tick the box for the sites the
routes already place, and the picker stops asking about them. The options page
lists what has been remembered and forgets any of it.

** Unsigned, like the other two

This Zen build reports ~MOZ_REQUIRE_SIGNING: false~, so an extension installed
from a store path loads without going near AMO. Sources are plain files rather
than a generated bundle, for the same reason =pkgs/tab-suspender= keeps its own
as plain files: an extension this size should be readable as the files it is.

#+begin_src nix
{
  lib,
  runCommand,
  zip,
}:
let
  addonId = "container-picker@nix-config";
in
#+end_src

* The layout is Firefox's, not ours

Gecko looks for extensions under a directory named after its own application
id, and the file has to be named for the extension's id or the browser will
not match the manifest to it. home-manager reads =passthru.addonId= to link the
result into the profile and to aim the settings at the right storage.

=-X= drops the platform's extra file attributes, which keeps the zip identical
between builds; the store's fixed timestamps do the rest.

#+begin_src nix
runCommand "container-picker-1.0.0"
  {
    nativeBuildInputs = [ zip ];

    passthru = {
      inherit addonId;
    };

    meta = {
      description = "Ask which container a link opened from outside the browser belongs in";
      platforms = lib.platforms.all;
    };
  }
  ''
    out_dir="$out/share/mozilla/extensions/{ec8030f7-c20a-464f-9b0e-13a3a9e97384}"
    mkdir -p "$out_dir" src
    cp -r ${./container-picker}/. src/
    chmod -R u+w src
    cd src
    zip -r -q -X "$out_dir/${addonId}.xpi" .
  ''
#+end_src
