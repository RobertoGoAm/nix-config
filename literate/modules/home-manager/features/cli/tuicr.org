* tuicr: review what an agent changed, the way a pull request is reviewed

Through home-manager's =programs.tuicr=, which installs it and writes
=~/.config/tuicr/config.toml= from =settings=; local themes would go under
=themes=. The package carries the Colemak key translation from
=overlays/tuicr-colemak.nix=, and =overlays/tuicr-chunks.nix= splits every hunk
at its unchanged lines, so =R= marks and folds one edit at a time, and =R= over
a =V= selection marks and folds just those lines.

Its colours follow the system appearance with the tokyonight the editors use:
storm when dark, day when light. Everything else keeps tuicr's defaults; the
options are listed in its docs/CONFIG.md.

* The agent side: tuicr's skill, taught to open tabs in Orca

tuicr ships a skill for coding agents in =skills/tuicr= of its source: the
=tuicr review= commands an agent uses to find a review session and read the
comments left in it, and wrappers that open tuicr in a split pane of cmux,
tmux, Zellij or Herdr. Orca is none of those, so this adds
=tuicr-wrapper-orca.sh= beside them (it lives next to this module): it opens
tuicr in a new terminal tab of the worktree with =orca terminal create= and,
like the cmux wrapper, returns at once with the tab's handle. The skill's
launcher table gets an Orca row and a Herdr desktop row (a herdr-core
terminal, =$HC_TERMINAL_ID=, where =$HERDR_ENV= is unset), and sections on
both and on the pull
requests that open by themselves (=tuicr-skill-agents.md=, also beside this
module). The skill comes from tuicr's own source, so nothing
private is declared here; the reason the Claude module leaves skills alone
does not apply. Shebangs are pinned to nix's bash, whose arrays behave under
=set -u= where macOS's bash 3.2 does not, and the wrapper finds =jq= without
relying on the shell's PATH.

#+begin_src nix
{
  config,
  lib,
  pkgs,
  ...
}:
let
  skill = pkgs.runCommand "tuicr-skill" { } ''
    cp -r ${config.programs.tuicr.package.src}/skills/tuicr $out
    chmod -R u+w $out
    install -m 755 ${./tuicr-wrapper-orca.sh} $out/tuicr-wrapper-orca.sh
    substituteInPlace $out/tuicr-wrapper-orca.sh \
      --subst-var-by runtimePath ${lib.makeBinPath [ pkgs.jq ]}
    substituteInPlace $out/SKILL.md --replace-fail \
      'launch tuicr in cmux, tmux, Zellij, or Herdr when' \
      'launch tuicr in Orca, cmux, tmux, Zellij, or Herdr when'
    awk -v row='| `$ORCA_AGENT_SESSION_ID` is set | Run `tuicr-wrapper-orca.sh /path/to/repo -- <scope>` (see **Orca** below) |' \
      -v app='| `$HC_TERMINAL_ID` is set and `$HERDR_ENV` is not | Open a pane with `hc run` in your own tab (see **Herdr desktop** below) |' '
      index($0, "| `$CMUX_WORKSPACE_ID` is set |") == 1 { print row; print app; found = 1 }
      { print }
      END { exit !found }' $out/SKILL.md > SKILL.md
    cat SKILL.md ${./tuicr-skill-agents.md} > $out/SKILL.md
    patchShebangs $out
  '';
#+end_src

* Pull requests an agent opens land in tuicr by themselves

A PostToolUse hook watches Bash calls made inside Herdr or Orca. When one
created a pull or merge request (=gh pr create=, =glab mr create=, or
=df mr-generate=, which wraps the latter) and its output carries the
request's URL, the hook opens =tuicr pr <url>= beside the agent and hands it
the URL, where the review is and how to read it back, so it waits for the
owner's comments instead of opening a second review. Inside a Herdr pane
(=HERDR_ENV=1=, checked first, since Herdr can itself run in an Orca tab) the
agent's pane is split and tuicr runs in the new half; tuicr's own Herdr
wrapper waits for the review to end, which would hold the agent up, so the
hook splits and runs without waiting. Inside Herdr desktop (=HC_TERMINAL_ID=
set, checked next) the review opens as a new tab in the agent's own space,
named after the request (=#123 Fix login=, or =!45 Fix login= for a GitLab
merge request, from =gh= or =glab=) so the picker finds it, and takes the
focus, through the app's own =tab.new=. For an agent on another machine than
the window it starts instead as a herdr-core terminal labelled with the
agent's space and a new tab id, which makes it a new tab there that Herdr
names on its own. The agent's
terminal gets =review.url=, =review.terminal= and =review.title= labels, which the agents-plus
mod in =herdr.org= reads to show the request and its CI beside the agent's row.
Inside Orca it opens a tab through the Orca wrapper. Anything else, and every
call outside all three, passes untouched.
Inside Herdr desktop the review opens as a new tab in the agent's own space,
named after the request, in the background: Herdr's =tab.new= with =focus:
false= leaves the shown space, its selected tab and the keyboard where they
were, so the owner is never moved off what they are doing, and the request is
there for them in the picker, from the agent's row or its PR pill. Herdr has no
way to make a tab the selected one of a space without showing it, so the tab is
not selected either.

A GitLab merge request skips tuicr when the agent's space has an MRs tab
(=mr-review.org=): it is reviewed there, with GitLab's own draft notes. The
hook only labels the agent's terminal with the request, =review.view=mrs= and
=review.at=, the time; the MRs tab of that space reads the labels and selects
the request the next time it is drawn, and the agent is told to read the
owner's drafts back with =mr-review show=. Nothing is shown or focused here
either: the pill and =Cmd+Shift+R= show the tab, selected. A GitHub pull
request, or a space whose MRs tab was closed, still gets tuicr.

The script follows. It is tangled to =tuicr-review-hook.sh= beside the module,
like the Nix around it, so it is edited here and never in that file.

#+begin_src bash :tangle (concat (file-name-directory (my/lit-target)) "tuicr-review-hook.sh") :comments no
#!/usr/bin/env bash
# Claude Code PostToolUse hook: after a Bash call that opened a pull or merge
# request, open it in tuicr for the owner to review, and tell the agent where
# the review lives. In the Herdr TUI it splits the agent's pane; in Herdr
# desktop it opens a background tab in the agent's space; in Orca, a new tab.
# Anywhere else, or when the command did not open a request, it does nothing.
set -u -o pipefail

PATH="@runtimePath@:$PATH"
ORCA_WRAPPER="@orcaWrapper@"
HERDR_BIN="${HERDR_BIN:-herdr}"

if [[ "${HERDR_ENV:-}" == "1" ]]; then
  host=herdr
elif [[ -n "${HC_TERMINAL_ID:-}" ]] && command -v hc >/dev/null; then
  host=herdr-app
elif [[ -n "${ORCA_AGENT_SESSION_ID:-}" ]]; then
  host=orca
else
  exit 0
fi

input="$(cat)"
command="$(jq -r '.tool_input.command // ""' <<<"$input")"
case "$command" in
  *"gh pr create"* | *"glab mr create"* | *"df mr-generate"*) ;;
  *) exit 0 ;;
esac

output="$(jq -r '.tool_response | if type == "object"
  then [.stdout, .stderr] | map(select(. != null)) | join("\n")
  else tostring end' <<<"$input")"
url="$(grep -oE 'https?://[^[:space:]"'\''<>()]+/(pull/[0-9]+|-/merge_requests/[0-9]+)' <<<"$output" | tail -1 || true)"
[[ -n "$url" ]] || exit 0

cwd="$(jq -r '.cwd // empty' <<<"$input")"
cwd="${cwd:-$PWD}"

context() {
  jq -n --arg text "$1" \
    '{hookSpecificOutput: {hookEventName: "PostToolUse", additionalContext: $text}}'
}

read_back="When they say the review is done, find the session with \`tuicr review list --repo $cwd\` (kind \"pr\") and read their comments with \`tuicr review comments --session <slug>\`, as the tuicr skill describes."

# Splits the agent's own pane, or the focused one if Herdr does not know that
# id, and runs tuicr in the new pane without waiting for it. The pane's shell
# may not be bash, so tuicr runs under `bash -c` with a single-quoted script;
# the pane closes itself when tuicr exits cleanly.
open_in_herdr() {
  local split pane script
  split="$("$HERDR_BIN" pane split "${HERDR_PANE_ID:-}" --direction right --cwd "$cwd" --focus 2>/dev/null \
    || "$HERDR_BIN" pane split --current --direction right --cwd "$cwd" --focus)" || return 1
  pane="$(jq -er '.result.pane.pane_id' <<<"$split")" || return 1
  script="tuicr pr $(printf '%q' "$url")"
  "$HERDR_BIN" pane run "$pane" "bash -c '${script//\'/\'\\\'\'}' && exit" >/dev/null || return 1
  printf '%s' "$pane"
}

# Herdr desktop: the review opens as a new tab in the agent's own space, named
# after the request ("#123 Fix login" or "!45 Fix login") so the picker finds
# it, in the background: the owner's view never moves. Where the app does not
# run on the agent's machine (an agent on another Mac), herdr-core starts it as
# a new tab of that space, which Herdr names on its own. The agent's terminal
# is labelled with the request's URL and the review's terminal, which the
# agents-plus mod reads to draw the PR pill with its CI state and to bring the
# review back.
review_title() {
  local t
  case "$url" in
    */pull/*)
      t="$(gh pr view "$url" --json number,title --jq 'select(.number != null) | "#\(.number) \(.title)"' 2>/dev/null)" ;;
    */-/merge_requests/*)
      t="$(glab mr view "${url##*/}" -R "${url%%/-/merge_requests/*}" -F json 2>/dev/null \
        | jq -r 'select(.iid != null) | "!\(.iid) \(.title)"' 2>/dev/null)" ;;
  esac
  if [[ -z "$t" ]]; then
    case "$url" in
      */pull/*) t="#${url##*/}" ;;
      *) t="!${url##*/}" ;;
    esac
  fi
  printf '%s' "${t:0:60}"
}

# The space's MRs tab, by the name the requests mod gives it, or nothing.
mrs_tab() {
  herdr-app ls 2>/dev/null | jq -r --arg s "$1" \
    'first(.. | objects | select(.tabs? and .id == $s) | .tabs[] | select(.name | startswith("MRs · ")) | .name) // empty'
}

open_in_mrs() {
  local me="$HC_TERMINAL_ID" info space tab title
  [[ "$url" == */-/merge_requests/* ]] && command -v herdr-app >/dev/null || return 1
  info="$(hc get "$me" --json)" || return 1
  space="$(jq -er '.labels["herdr.space"]' <<<"$info")" || return 1
  tab="$(mrs_tab "$space")"
  [[ -n "$tab" ]] || return 1
  title="$(review_title)"
  hc label "$me" "review.url=$url" "review.title=$title" "review.view=mrs" "review.at=$(date +%s)" "review.terminal=" >/dev/null || return 1
  printf '%s' "$tab"
}

open_in_herdr_app() {
  local me="$HC_TERMINAL_ID" info space run addr argv title
  info="$(hc get "$me" --json)" || return 1
  space="$(jq -er '.labels["herdr.space"]' <<<"$info")" || return 1
  title="$(review_title)"
  argv="$(jq -cn --arg url "$url" '["tuicr", "pr", $url]')"
  if command -v herdr-app >/dev/null \
    && run="$(herdr-app do tab.new --space "$space" --name "$title" --folder "$cwd" --argv "$argv" --focus false 2>/dev/null)" \
    && addr="$(jq -er '.terminal' <<<"$run")"; then
    :
  else
    run="$(hc run --bg --json --no-parent --no-notify --rm --cwd "$cwd" \
      --label "herdr.space=$space" --label "herdr.tab=tbreview$(date +%s)$RANDOM" -- tuicr pr "$url")" || return 1
    addr="$(jq -er '.address' <<<"$run")" || return 1
  fi
  hc label "$me" "review.url=$url" "review.terminal=$addr" "review.title=$title" "review.view=" >/dev/null || true
  printf '%s\t%s' "$addr" "$title"
}

case "$host" in
  herdr-app)
    if tab="$(open_in_mrs 2>/dev/null)"; then
      context "$url is open for review in this space's \"$tab\" tab, where the user reviews GitLab merge requests with nvim's keys inside Herdr. It was not shown, so their view did not move; do not open tuicr or anything else for it, and do not focus it. Tell the user it is ready: Cmd+Shift+R from your row, or the PR pill, which also shows its CI state, brings the tab up on it. Their comments are GitLab draft notes, which only they see until they publish them. When they say the review is done, read them with \`mr-review show $cwd ${url##*/} | jq '{drafts, threads}'\`: each draft has its body, \`at\` (path, old_line and new_line; null for one on the whole merge request) and \`reply_to\`, the id of the thread in \`threads\` it answers. Publishing or dropping their drafts is theirs to do, not yours."
    elif opened="$(open_in_herdr_app 2>&1)"; then
      term="${opened%%$'\t'*}"
      title="${opened#*$'\t'}"
      context "tuicr is now open on $url in a new Herdr tab named \"$title\" in this space (terminal $term), opened in the background so the user's view did not move; do not open another, and do not focus it. Tell the user it is ready: they reach it with Cmd+P by that title, Cmd+Shift+R from your row, or the PR pill, which also shows its CI state. $read_back The tab holds only that terminal, so \`hc kill $term\` closes it once it is no longer needed."
    else
      context "Opening tuicr on $url in a Herdr tab failed: $opened. Tell the user they can run \`tuicr pr $url\` themselves."
    fi
    ;;
  herdr)
    if pane="$(open_in_herdr 2>&1)"; then
      context "tuicr is now open on $url in Herdr pane $pane, beside this one, for the user to review; do not open another. $read_back Close the pane with \`herdr pane close $pane\` once it is no longer needed."
    else
      context "Opening tuicr on $url in a Herdr pane failed: $pane. Tell the user they can run \`tuicr pr $url\` themselves."
    fi
    ;;
  orca)
    if launched="$("$ORCA_WRAPPER" "$cwd" -- pr "$url" 2>&1)"; then
      handle="$(sed -n '/^=== TUICR TERMINAL ===$/{n;p;}' <<<"$launched")"
      context "tuicr is now open on $url in Orca terminal $handle, for the user to review; do not open another. $read_back Close the tab with \`orca terminal close --terminal $handle\` once it is no longer needed."
    else
      context "Opening tuicr on $url in an Orca tab failed: $launched. Tell the user they can run \`tuicr pr $url\` themselves."
    fi
    ;;
esac
#+end_src

* The hook is tested when it is built

=tuicr-review-hook-test.sh= runs the hook against stand-in =hc=, =herdr-app=
and =gh= for the Herdr desktop case and fails the build when it no longer opens
a background tab named after the request in the agent's space, labels the
agent's terminal, or tells the agent about a tab and how to close it, or when
it moves the owner's view; and when a merge request in a space with an MRs
tab is not handed to that tab through the labels, or opens anything.

#+begin_src bash :tangle (concat (file-name-directory (my/lit-target)) "tuicr-review-hook-test.sh") :comments no
#!/usr/bin/env bash
# Runs the review hook against stand-in hc, herdr-app and gh for the Herdr
# desktop case, and fails when it stops opening a background tab named after
# the request in the agent's space, labelling the agent's terminal, or telling
# the agent about a tab; or when it starts moving the owner's view.
set -euo pipefail

hook="$1"
work="$(mktemp -d)"
stubs="$work/bin"
calls="$work/calls"
mkdir -p "$stubs"
: > "$calls"

stub() {
  { printf '#!%s\n' "$BASH"; cat; } > "$stubs/$1"
  chmod +x "$stubs/$1"
}

stub hc <<'EOF'
echo "hc $*" >> "$CALLS"
case "$1" in
  get) echo '{"labels":{"herdr.space":"sp-test","herdr.tab":"tb-agent"}}' ;;
esac
EOF

stub herdr-app <<'EOF'
echo "herdr-app $*" >> "$CALLS"
case "$1" in
  ls) echo '{"spaces":[{"id":"sp-test","tabs":[{"id":"tb-mrs","name":"MRs · repo"}]}]}' ;;
  *) echo '{"space":"sp-test","tab":"tb-review","terminal":"t9"}' ;;
esac
EOF

stub glab <<'EOF'
echo '{"iid":12,"title":"Fix the logout"}'
EOF

stub gh <<'EOF'
echo '#7 Fix the login'
EOF

input='{"tool_input":{"command":"gh pr create --fill"},"tool_response":{"stdout":"https://github.com/owner/repo/pull/7\n"},"cwd":"/tmp/repo"}'
out="$(CALLS="$calls" HC_TERMINAL_ID=t1 PATH="$stubs:$PATH" bash "$hook" <<<"$input")"

fail() {
  echo "tuicr review hook test: $1" >&2
  echo "--- calls" >&2
  cat "$calls" >&2
  echo "--- output" >&2
  echo "$out" >&2
  exit 1
}

grep -qxF 'herdr-app do tab.new --space sp-test --name #7 Fix the login --folder /tmp/repo --argv ["tuicr","pr","https://github.com/owner/repo/pull/7"] --focus false' "$calls" \
  || fail "no background tab.new named after the request in the agent's space"
grep -qxF 'hc label t1 review.url=https://github.com/owner/repo/pull/7 review.terminal=t9 review.title=#7 Fix the login review.view=' "$calls" \
  || fail "the agent's terminal was not labelled with the request and its review"
if grep -qE 'pane\.focus|tab\.select|space\.select|agent\.focus' "$calls"; then
  fail "the hook moved the owner's view"
fi
jq -e '.hookSpecificOutput.additionalContext
  | test("new Herdr tab") and test("hc kill t9") and (test("pane") | not)' <<<"$out" >/dev/null \
  || fail "the context does not describe a tab and how to close it"
echo "tuicr review hook: Herdr desktop case passes"

: > "$calls"
input='{"tool_input":{"command":"glab mr create --fill"},"tool_response":{"stdout":"https://gitlab.example.com/group/repo/-/merge_requests/12\n"},"cwd":"/tmp/repo"}'
out="$(CALLS="$calls" HC_TERMINAL_ID=t1 PATH="$stubs:$PATH" bash "$hook" <<<"$input")"
grep -qE '^hc label t1 review\.url=https://gitlab\.example\.com/group/repo/-/merge_requests/12 review\.title=!12 Fix the logout review\.view=mrs review\.at=[0-9]+ review\.terminal=$' "$calls" \
  || fail "a merge request was not handed to the space's MRs tab through the agent's labels"
if grep -qE 'tab\.new|tuicr|pane\.focus|tab\.select|space\.select' "$calls"; then
  fail "a merge request with an MRs tab opened a tab or moved the owner's view"
fi
jq -e '.hookSpecificOutput.additionalContext
  | test("MRs · repo") and test("mr-review show /tmp/repo 12") and (test("tuicr pr") | not)' <<<"$out" >/dev/null \
  || fail "the context does not point the agent at the MRs tab and its drafts"
echo "tuicr review hook: merge request to the MRs tab passes"
#+end_src

* A list of the repository's open requests to review

=tuicr pr= reviews one request and has no list to choose from, so
=tuicr-prs= (=tuicr-prs.sh= beside this module) is one: the repository's open
pull requests (=gh=) or merge requests (=glab=), chosen by the =origin=
remote, in fzf with their number, title, author, branch and review state.
Enter opens the one picked in =tuicr pr=, and leaving tuicr comes back to the
list; =ctrl-r= reloads it and Esc leaves. The Herdr launcher can open it in a
tab of its own beside a new session.

#+begin_src nix
  home.packages = [
    (pkgs.runCommand "tuicr-prs" { } ''
      install -Dm755 ${./tuicr-prs.sh} $out/bin/tuicr-prs
      substituteInPlace $out/bin/tuicr-prs \
        --replace-fail 'set -u -o pipefail' 'set -u -o pipefail
      PATH="${lib.makeBinPath [ pkgs.fzf pkgs.jq ]}:$PATH"'
      patchShebangs $out/bin
    '')
  ];
#+end_src

* Orca profiles that keep their own skills folder

Orca runs Claude from a profile directory of its own, and links that
profile's =skills= to =~/.claude/skills= only when the latter existed when the
profile was made. A profile created before it (vulcan's personal one) has a
real folder instead, so the skill is linked into each such folder too. Writing
under =~/Library/Application Support= can be refused by macOS's privacy
controls depending on which app ran the rebuild, so a refusal is reported
rather than failing the switch.

#+begin_src nix
  home.activation.tuicrSkillInOrcaProfiles = lib.hm.dag.entryAfter [ "linkGeneration" ] ''
    for skills in "$HOME/Library/Application Support/orca/claude-profiles"/*/home/skills; do
      if [ -d "$skills" ] && [ ! -L "$skills" ]; then
        run ln -sfn "$HOME/.claude/skills/tuicr" "$skills/tuicr" \
          || warnEcho "could not link the tuicr skill into $skills"
      fi
    done
  '';
}
#+end_src
