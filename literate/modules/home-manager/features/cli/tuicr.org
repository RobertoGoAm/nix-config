* tuicr: review what an agent changed, the way a pull request is reviewed

Through home-manager's =programs.tuicr=, which installs it and writes
=~/.config/tuicr/config.toml= from =settings=; local themes would go under
=themes=. The package carries the Colemak key translation from
=overlays/tuicr-colemak.nix=, and =overlays/tuicr-chunks.nix= splits every hunk
at its unchanged lines, so =R= marks and folds one edit at a time, and =R= over
a =V= selection marks and folds just those lines.

Its colours follow the system appearance with the tokyonight the editors use:
storm when dark, day when light. Everything else keeps tuicr's defaults; the
options are listed in its docs/CONFIG.md.

* The agent side: tuicr's skill, taught to open tabs in Orca

tuicr ships a skill for coding agents in =skills/tuicr= of its source: the
=tuicr review= commands an agent uses to find a review session and read the
comments left in it, and wrappers that open tuicr in a split pane of cmux,
tmux, Zellij or Herdr. Orca is none of those, so this adds
=tuicr-wrapper-orca.sh= beside them (it lives next to this module): it opens
tuicr in a new terminal tab of the worktree with =orca terminal create= and,
like the cmux wrapper, returns at once with the tab's handle. The skill's
launcher table gets an Orca row and a Herdr desktop row (a herdr-core
terminal, =$HC_TERMINAL_ID=, where =$HERDR_ENV= is unset), and sections on
both and on the pull
requests that open by themselves (=tuicr-skill-agents.md=, also beside this
module). The skill comes from tuicr's own source, so nothing
private is declared here; the reason the Claude module leaves skills alone
does not apply. Shebangs are pinned to nix's bash, whose arrays behave under
=set -u= where macOS's bash 3.2 does not, and the wrapper finds =jq= without
relying on the shell's PATH.

#+begin_src nix
{
  config,
  lib,
  pkgs,
  ...
}:
let
  skill = pkgs.runCommand "tuicr-skill" { } ''
    cp -r ${config.programs.tuicr.package.src}/skills/tuicr $out
    chmod -R u+w $out
    install -m 755 ${./tuicr-wrapper-orca.sh} $out/tuicr-wrapper-orca.sh
    substituteInPlace $out/tuicr-wrapper-orca.sh \
      --subst-var-by runtimePath ${lib.makeBinPath [ pkgs.jq ]}
    substituteInPlace $out/SKILL.md --replace-fail \
      'launch tuicr in cmux, tmux, Zellij, or Herdr when' \
      'launch tuicr in Orca, cmux, tmux, Zellij, or Herdr when'
    awk -v row='| `$ORCA_AGENT_SESSION_ID` is set | Run `tuicr-wrapper-orca.sh /path/to/repo -- <scope>` (see **Orca** below) |' \
      -v app='| `$HC_TERMINAL_ID` is set and `$HERDR_ENV` is not | Open a pane with `hc run` in your own tab (see **Herdr desktop** below) |' '
      index($0, "| `$CMUX_WORKSPACE_ID` is set |") == 1 { print row; print app; found = 1 }
      { print }
      END { exit !found }' $out/SKILL.md > SKILL.md
    cat SKILL.md ${./tuicr-skill-agents.md} > $out/SKILL.md
    patchShebangs $out
  '';
#+end_src

* Pull requests an agent opens land in a review by themselves

A PostToolUse hook watches Bash calls made inside Herdr or Orca. When one
created a pull or merge request (=gh pr create=, =glab mr create=, or
=df mr-generate=, which wraps the latter) and its output carries the
request's URL, the hook puts the request up for review and hands the agent
the URL, where the review is and how to read it back, so it waits for the
owner's comments instead of opening a second review. Inside a Herdr pane
(=HERDR_ENV=1=, checked first, since Herdr can itself run in an Orca tab) the
agent's pane is split and =tuicr pr <url>= runs in the new half; tuicr's own
Herdr wrapper waits for the review to end, which would hold the agent up, so
the hook splits and runs without waiting. Inside Orca it opens a tuicr tab
through the Orca wrapper. Inside Herdr desktop (=HC_TERMINAL_ID= set, checked
next) it goes to an MRs tab, below. Anything else, and every call outside all
three, passes untouched.

Inside Herdr desktop a merge or pull request never goes to tuicr: it is
reviewed in an MRs tab (=mr-review.org=), with GitLab's draft notes or
GitHub's pending review. The request's checkout comes from =mr-review where=,
by its origin: the agent's own repository, or one beside it, as when an agent
in one repository opens requests in the packages next to it. The space's own
repository is reviewed in the space's MRs tab, whatever the requests mod named
it; another repository in a tab of its own, =MRs · <name>=, with its own
selection and progress (=scope=). The hook labels the agent's terminal with
the request, =review.view=mrs=, =review.at=, the time, and =review.folder=
for another repository's tab, and opens the tab in the background when the
space has none; the tab reads the labels and selects the request the next
time it is drawn, and the agent is told to read the owner's drafts back with
=mr-review show=. Nothing is shown or focused: the pill and =Cmd+Shift+R= show
the tab, selected. On a machine with no Herdr window (an agent on vulcan, its
space shown by the window on another Mac) the hook cannot see or open the
space's tabs, so it only labels: the window's tab takes it, or the pill opens
one. A request whose checkout is nowhere near the agent is only named to it.

The script follows. It is tangled to =tuicr-review-hook.sh= beside the module,
like the Nix around it, so it is edited here and never in that file.

#+begin_src bash :tangle (concat (file-name-directory (my/lit-target)) "tuicr-review-hook.sh") :comments no
#!/usr/bin/env bash
# Claude Code PostToolUse hook: after a Bash call that opened a pull or merge
# request, put it up for the owner to review, and tell the agent where the
# review lives. In the Herdr TUI it splits the agent's pane for tuicr; in Orca
# it opens a tuicr tab; in Herdr desktop it hands it to an MRs tab.
# Anywhere else, or when the command did not open a request, it does nothing.
set -u -o pipefail

PATH="@runtimePath@:$PATH"
ORCA_WRAPPER="@orcaWrapper@"
HERDR_BIN="${HERDR_BIN:-herdr}"

if [[ "${HERDR_ENV:-}" == "1" ]]; then
  host=herdr
elif [[ -n "${HC_TERMINAL_ID:-}" ]] && command -v hc >/dev/null; then
  host=herdr-app
elif [[ -n "${ORCA_AGENT_SESSION_ID:-}" ]]; then
  host=orca
else
  exit 0
fi

input="$(cat)"
command="$(jq -r '.tool_input.command // ""' <<<"$input")"
case "$command" in
  *"gh pr create"* | *"glab mr create"* | *"df mr-generate"*) ;;
  *) exit 0 ;;
esac

output="$(jq -r '.tool_response | if type == "object"
  then [.stdout, .stderr] | map(select(. != null)) | join("\n")
  else tostring end' <<<"$input")"
url="$(grep -oE 'https?://[^[:space:]"'\''<>()]+/(pull/[0-9]+|-/merge_requests/[0-9]+)' <<<"$output" | tail -1 || true)"
[[ -n "$url" ]] || exit 0

cwd="$(jq -r '.cwd // empty' <<<"$input")"
cwd="${cwd:-$PWD}"

context() {
  jq -n --arg text "$1" \
    '{hookSpecificOutput: {hookEventName: "PostToolUse", additionalContext: $text}}'
}

read_back="When they say the review is done, find the session with \`tuicr review list --repo $cwd\` (kind \"pr\") and read their comments with \`tuicr review comments --session <slug>\`, as the tuicr skill describes."

# Splits the agent's own pane, or the focused one if Herdr does not know that
# id, and runs tuicr in the new pane without waiting for it. The pane's shell
# may not be bash, so tuicr runs under `bash -c` with a single-quoted script;
# the pane closes itself when tuicr exits cleanly.
open_in_herdr() {
  local split pane script
  split="$("$HERDR_BIN" pane split "${HERDR_PANE_ID:-}" --direction right --cwd "$cwd" --focus 2>/dev/null \
    || "$HERDR_BIN" pane split --current --direction right --cwd "$cwd" --focus)" || return 1
  pane="$(jq -er '.result.pane.pane_id' <<<"$split")" || return 1
  script="tuicr pr $(printf '%q' "$url")"
  "$HERDR_BIN" pane run "$pane" "bash -c '${script//\'/\'\\\'\'}' && exit" >/dev/null || return 1
  printf '%s' "$pane"
}

# The request's name for its tab and the agent's pill: "#123 Fix login" or
# "!45 Fix login".
review_title() {
  local t
  case "$url" in
    */pull/*)
      t="$(gh pr view "$url" --json number,title --jq 'select(.number != null) | "#\(.number) \(.title)"' 2>/dev/null)" ;;
    */-/merge_requests/*)
      t="$(glab mr view "${url##*/}" -R "${url%%/-/merge_requests/*}" -F json 2>/dev/null \
        | jq -r 'select(.iid != null) | "!\(.iid) \(.title)"' 2>/dev/null)" ;;
  esac
  if [[ -z "$t" ]]; then
    case "$url" in
      */pull/*) t="#${url##*/}" ;;
      *) t="!${url##*/}" ;;
    esac
  fi
  printf '%s' "${t:0:60}"
}

# The MRs tab for the request: the space's own when the request is on the
# space's repository (the first "MRs · " tab, whatever the requests mod named
# it), and otherwise "MRs · <repository>", with its own selection and progress
# (scope). It is opened in the background when the space has none. The agent's
# terminal is labelled first, so the new tab finds the request when it starts.
# With no Herdr window on this machine to ask, the window elsewhere that shows
# the space is trusted to have the tab, or the PR pill opens it.
open_in_mrs() {
  local me="$HC_TERMINAL_ID" info space repo layout home own tab name props title
  [[ "$url" == */-/merge_requests/* || "$url" == */pull/* ]] || return 1
  info="$(hc get "$me" --json)" || return 1
  space="$(jq -er '.labels["herdr.space"]' <<<"$info")" || return 1
  repo="$(mr-review where "$url" "$cwd" 2>/dev/null | jq -er '.dir')" || return 1
  layout="$(herdr-app ls 2>/dev/null)" || layout=""
  home="$(jq -r --arg s "$space" 'first(.. | objects | select(.tabs? and .id == $s) | .folder // empty) // empty' <<<"${layout:-null}")"
  home="${home:-$cwd}"
  home="$(git -C "$home" rev-parse --show-toplevel 2>/dev/null || printf '%s' "$home")"
  own=false
  [[ "$repo" == "$home" ]] && own=true
  name="MRs · ${repo##*/}"
  title="$(review_title)"
  hc label "$me" "review.url=$url" "review.title=$title" "review.view=mrs" "review.at=$(date +%s)" \
    "review.folder=$([[ $own == true ]] || printf '%s' "$repo")" "review.terminal=" >/dev/null || return 1
  if [[ -z "$layout" ]]; then
    printf '%s\t%s' "$name" "$repo"
    return
  fi
  tab="$(jq -r --arg s "$space" --arg n "$name" --argjson own "$own" '
    [.. | objects | select(.tabs? and .id == $s) | .tabs[] | .name | select(startswith("MRs · "))] as $t
    | if ($t | index($n)) != null then $n elif $own and ($t | length) > 0 then $t[0] else "" end' <<<"$layout")"
  if [[ -z "$tab" ]]; then
    props="$(jq -cn --arg f "$repo" --arg s "$space" --argjson own "$own" \
      '{folder: $f, space: $s} + (if $own then {} else {scope: "\($s)|\($f)"} end)')"
    herdr-app do tab.new --space "$space" --name "$name" --mod mrs --props "$props" --focus false >/dev/null || return 1
    tab="$name"
  fi
  printf '%s\t%s' "$tab" "$repo"
}

case "$host" in
  herdr-app)
    if opened="$(open_in_mrs 2>/dev/null)"; then
      tab="${opened%%$'\t'*}"
      repo="${opened#*$'\t'}"
      context "$url is open for review in this space's \"$tab\" tab, where the user reviews merge and pull requests with nvim's keys inside Herdr. It was not shown, so their view did not move; do not open tuicr or anything else for it, and do not focus it. Tell the user it is ready: Cmd+Shift+R from your row, or the PR pill, which also shows its CI state, brings the tab up on it. Their comments are drafts (GitLab draft notes, or GitHub's pending review), which only they see until they publish them. When they say the review is done, read them with \`mr-review show $repo ${url##*/} | jq '{drafts, threads}'\`: each draft has its body, \`at\` (path, old_line and new_line; null for one on the whole request) and \`reply_to\`, the id of the thread in \`threads\` it answers. Publishing or dropping their drafts is theirs to do, not yours."
    else
      context "$url has no checkout on this machine in or beside $cwd, so it could not be put in an MRs tab for review. Tell the user the request is open at $url; do not open tuicr for it."
    fi
    ;;
  herdr)
    if pane="$(open_in_herdr 2>&1)"; then
      context "tuicr is now open on $url in Herdr pane $pane, beside this one, for the user to review; do not open another. $read_back Close the pane with \`herdr pane close $pane\` once it is no longer needed."
    else
      context "Opening tuicr on $url in a Herdr pane failed: $pane. Tell the user they can run \`tuicr pr $url\` themselves."
    fi
    ;;
  orca)
    if launched="$("$ORCA_WRAPPER" "$cwd" -- pr "$url" 2>&1)"; then
      handle="$(sed -n '/^=== TUICR TERMINAL ===$/{n;p;}' <<<"$launched")"
      context "tuicr is now open on $url in Orca terminal $handle, for the user to review; do not open another. $read_back Close the tab with \`orca terminal close --terminal $handle\` once it is no longer needed."
    else
      context "Opening tuicr on $url in an Orca tab failed: $launched. Tell the user they can run \`tuicr pr $url\` themselves."
    fi
    ;;
esac
#+end_src

* The hook is tested when it is built

=tuicr-review-hook-test.sh= runs the hook against stand-in =hc=, =herdr-app=,
=mr-review=, =glab= and =gh= for the Herdr desktop case, and fails the build
when a request opens tuicr or moves the owner's view; when one on the space's
repository is not handed to the space's MRs tab through the agent's labels, or
the tab is not opened in the background when the space has none; when one on
a repository beside it does not get a tab of its own with its own progress;
when one on a machine with no Herdr window is not left to the window's tab;
and when the agent is not told where to read the drafts back.

#+begin_src bash :tangle (concat (file-name-directory (my/lit-target)) "tuicr-review-hook-test.sh") :comments no
#!/usr/bin/env bash
# Runs the review hook against stand-ins for the Herdr desktop case, and fails
# when a request opens tuicr or moves the owner's view, or is not handed to the
# right MRs tab, opened in the background when the space has none.
set -euo pipefail

hook="$1"
work="$(mktemp -d)"
stubs="$work/bin"
calls="$work/calls"
mkdir -p "$stubs"

stub() {
  { printf '#!%s\n' "$BASH"; cat; } > "$stubs/$1"
  chmod +x "$stubs/$1"
}

stub hc <<'EOF'
echo "hc $*" >> "$CALLS"
case "$1" in
  get) echo '{"labels":{"herdr.space":"sp-test","herdr.tab":"tb-agent"}}' ;;
esac
EOF

stub herdr-app <<'EOF'
echo "herdr-app $*" >> "$CALLS"
case "$1" in
  ls) [ -n "${NO_WINDOW:-}" ] && exit 1
      if [ -n "${NO_MRS:-}" ]; then echo '{"spaces":[{"id":"sp-test","folder":"/tmp/repo","tabs":[]}]}'
      else echo '{"spaces":[{"id":"sp-test","folder":"/tmp/repo","tabs":[{"id":"tb-mrs","name":"MRs · repo"}]}]}'; fi ;;
  *) echo '{"space":"sp-test","tab":"tb-new","pane":"p9"}' ;;
esac
EOF

stub mr-review <<'EOF'
echo "mr-review $*" >> "$CALLS"
[ "$1" = where ] || exit 1
[ -n "${NO_CHECKOUT:-}" ] && { echo '{"error":"no checkout"}'; exit 1; }
echo "{\"dir\":\"${WHERE:-/tmp/repo}\"}"
EOF

stub glab <<'EOF'
echo '{"iid":12,"title":"Fix the logout"}'
EOF

stub gh <<'EOF'
echo '#7 Fix the login'
EOF

mr='{"tool_input":{"command":"glab mr create --fill"},"tool_response":{"stdout":"https://gitlab.example.com/group/repo/-/merge_requests/12\n"},"cwd":"/tmp/repo"}'
pr='{"tool_input":{"command":"gh pr create --fill"},"tool_response":{"stdout":"https://github.com/owner/repo/pull/7\n"},"cwd":"/tmp/repo"}'
out=""

hook() {
  : > "$calls"
  out="$(env CALLS="$calls" HC_TERMINAL_ID=t1 PATH="$stubs:$PATH" "$@" bash "$hook" <<<"$input")"
}

fail() {
  echo "tuicr review hook test: $1" >&2
  echo "--- calls" >&2
  cat "$calls" >&2
  echo "--- output" >&2
  echo "$out" >&2
  exit 1
}

calm() {
  if grep -qE 'tuicr|pane\.focus|tab\.select|space\.select|agent\.focus' "$calls"; then
    fail "$1 opened tuicr or moved the owner's view"
  fi
}

input="$mr"
hook
grep -qE '^hc label t1 review\.url=https://gitlab\.example\.com/group/repo/-/merge_requests/12 review\.title=!12 Fix the logout review\.view=mrs review\.at=[0-9]+ review\.folder= review\.terminal=$' "$calls" \
  || fail "a merge request was not handed to the space's MRs tab through the agent's labels"
grep -q 'tab\.new' "$calls" && fail "a space with an MRs tab got another"
calm "a merge request with an MRs tab"
jq -e '.hookSpecificOutput.additionalContext
  | test("MRs · repo") and test("mr-review show /tmp/repo 12") and (test("tuicr pr") | not)' <<<"$out" >/dev/null \
  || fail "the context does not point the agent at the MRs tab and its drafts"
echo "tuicr review hook: merge request to the space's MRs tab passes"

input="$pr"
hook NO_MRS=1
grep -qxF 'herdr-app do tab.new --space sp-test --name MRs · repo --mod mrs --props {"folder":"/tmp/repo","space":"sp-test"} --focus false' "$calls" \
  || fail "a space with no MRs tab did not get one in the background"
calm "a pull request in a space with no MRs tab"
echo "tuicr review hook: an MRs tab for a space with none passes"

input="$mr"
hook WHERE=/tmp/pkg
grep -qE '^hc label t1 .* review\.folder=/tmp/pkg review\.terminal=$' "$calls" \
  || fail "a request on the repository beside the space's was not labelled with its checkout"
grep -qxF 'herdr-app do tab.new --space sp-test --name MRs · pkg --mod mrs --props {"folder":"/tmp/pkg","space":"sp-test","scope":"sp-test|/tmp/pkg"} --focus false' "$calls" \
  || fail "a request on the repository beside the space's did not get a tab of its own"
calm "a request on another repository"
jq -e '.hookSpecificOutput.additionalContext | test("MRs · pkg") and test("mr-review show /tmp/pkg 12")' <<<"$out" >/dev/null \
  || fail "the context does not point the agent at the other repository's tab"
echo "tuicr review hook: a request on the repository beside it passes"

input="$pr"
hook NO_WINDOW=1
grep -qE '^hc label t1 review\.url=https://github\.com/owner/repo/pull/7 review\.title=#7 Fix the login review\.view=mrs review\.at=[0-9]+ review\.folder= review\.terminal=$' "$calls" \
  || fail "a pull request on a machine with no window was not handed to the MRs tab"
grep -q 'tab\.new' "$calls" && fail "a machine with no window was asked for a tab"
calm "a pull request with no window here"
echo "tuicr review hook: pull request with no window here passes"

input="$mr"
hook NO_CHECKOUT=1
calm "a request with no checkout near the agent"
jq -e '.hookSpecificOutput.additionalContext | test("no checkout")' <<<"$out" >/dev/null \
  || fail "the agent was not told the request has no checkout here"
echo "tuicr review hook: a request with no checkout here passes"
#+end_src

* A list of the repository's open requests to review

=tuicr pr= reviews one request and has no list to choose from, so
=tuicr-prs= (=tuicr-prs.sh= beside this module) is one: the repository's open
pull requests (=gh=) or merge requests (=glab=), chosen by the =origin=
remote, in fzf with their number, title, author, branch and review state.
Enter opens the one picked in =tuicr pr=, and leaving tuicr comes back to the
list; =ctrl-r= reloads it and Esc leaves. The Herdr launcher can open it in a
tab of its own beside a new session.

#+begin_src nix
  home.packages = [
    (pkgs.runCommand "tuicr-prs" { } ''
      install -Dm755 ${./tuicr-prs.sh} $out/bin/tuicr-prs
      substituteInPlace $out/bin/tuicr-prs \
        --replace-fail 'set -u -o pipefail' 'set -u -o pipefail
      PATH="${lib.makeBinPath [ pkgs.fzf pkgs.jq ]}:$PATH"'
      patchShebangs $out/bin
    '')
  ];
#+end_src

* Orca profiles that keep their own skills folder

Orca runs Claude from a profile directory of its own, and links that
profile's =skills= to =~/.claude/skills= only when the latter existed when the
profile was made. A profile created before it (vulcan's personal one) has a
real folder instead, so the skill is linked into each such folder too. Writing
under =~/Library/Application Support= can be refused by macOS's privacy
controls depending on which app ran the rebuild, so a refusal is reported
rather than failing the switch.

#+begin_src nix
  home.activation.tuicrSkillInOrcaProfiles = lib.hm.dag.entryAfter [ "linkGeneration" ] ''
    for skills in "$HOME/Library/Application Support/orca/claude-profiles"/*/home/skills; do
      if [ -d "$skills" ] && [ ! -L "$skills" ]; then
        run ln -sfn "$HOME/.claude/skills/tuicr" "$skills/tuicr" \
          || warnEcho "could not link the tuicr skill into $skills"
      fi
    done
  '';
}
#+end_src
