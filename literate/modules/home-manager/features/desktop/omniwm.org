* OmniWM, the other tiling window manager

Upstream home-manager carries =programs.omniwm=, so this module is mostly the
wiring: it installs the package, runs the app under a launchd agent, and is
gated on the same option that turns aerospace off.

Three requirements are not this file's to satisfy, and none of them fails
loudly. OmniWM needs Apple Silicon and macOS 26 or later, which this host has;
it needs Accessibility and Input Monitoring, which are granted by hand on
first launch; and it needs =Displays have separate Spaces= left on in Mission
Control settings. Without the permissions the agent starts and the window
manager simply does not manage anything.

#+begin_src nix
{
  config,
  lib,
  ...
}:
{
  imports = [ ./window-manager.nix ];

  programs.omniwm = {
    enable = config.features.desktop.windowManager == "omniwm";

    # KeepAlive, as the upstream module defaults it: a window manager that has
    # quit is a desktop with no window manager, which is worth a restart.
    launchd.enable = true;
  };
#+end_src

* The settings file is OmniWM's own, with three edits

Not a file written from scratch. OmniWM's README documents its behaviour and
its GUI rather than the key names, and a key invented against those does not
fail -- it is ignored, and the setting silently does not apply. What is tracked
here is the file OmniWM itself wrote on its first run, which is the schema
exactly as it round-trips, with three deliberate changes on top. The path form
is what upstream recommends for this, and the module re-links it on every
switch because OmniWM replaces the link with a regular file whenever its GUI
saves.

** The eight directional keys, as aerospace bound them

OmniWM ships focus and move on Option and Option+Shift with the arrow keys.
The rest of this config has had those four directions on =h n e i= for years --
left, down, up, right on Colemak's home row -- so they move here too. Nothing
else had to be touched: OmniWM already puts workspace switching on
=Option+1..9= and moving a window to one on =Option+Shift+1..9=, which is the
same arrangement =alt-1..6= and =alt-shift-1..6= had.

Checked for collisions rather than assumed: with these eight applied, no two
of the 67 bound hotkeys claim the same chord.

** Gaps of ten

aerospace ran ten inner and ten outer; OmniWM's own default is sixteen inner
and none outer. This keeps the spacing that was there before rather than the
one that came with the new manager.

** The CLI needs the socket

=ipcEnabled= ships =false=, and with it off =omniwmctl ping= answers "No such
file or directory" -- the IPC and CLI surface the README documents is simply
absent. Nothing here depends on it yet; it is on because a window manager that
can be driven from a script is the reason for choosing one with a CLI.

** Rules assign by the workspace's name, not its label

A workspace has a =name= and a =displayName=: OmniWM's own GUI creates them
named "1" through "5" and puts the readable label in =displayName=, which is
what the bar draws. =assignToWorkspace= matches the =name=.

This is worth spelling out because getting it wrong fails silently. A rule
saying =assignToWorkspace = "Media"= is reported valid by
=omniwmctl query rules=, shows "Media" in its WORKSPACE column, and does
nothing at all -- windows keep opening wherever you already were. Replacing
that one value with "4" and re-applying the rule moved the window
immediately, which is how the two were told apart.

So the rules below read 1 to 5, and the mapping is the workspace list further
down: 1 Main, 2 Code, 3 Work, 4 Media, 5 Misc.

** Copied, not linked

=programs.omniwm.settings= would take this path and symlink it in, which is
what it did until now -- and OmniWM could then never save anything of its own.
Renaming a workspace in its GUI appeared to work and was gone on the next
look: the store file is read-only, so the write failed, and nothing said so.
Adding a rule with =omniwmctl= behaves the same way; the rule takes effect in
memory and the file is untouched.

A copy makes the GUI work again and leaves this file the source of truth on
the same terms as every other app's preferences here: change it in the app, and
the next activation puts this back. Anything worth keeping gets folded in here
first.

#+begin_src nix
  home.activation.omniwmSettings = lib.mkIf (config.programs.omniwm.enable) (
    lib.hm.dag.entryAfter [ "writeBoundary" ] ''
      run mkdir -p "${config.xdg.configHome}/omniwm"
      run cp -f ${./omniwm-settings.toml} "${config.xdg.configHome}/omniwm/settings.toml"
      run chmod u+w "${config.xdg.configHome}/omniwm/settings.toml"
    ''
  );
}
#+end_src
